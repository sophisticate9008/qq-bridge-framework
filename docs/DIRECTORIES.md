# 目录与迁移

程序、持久数据、助手工作区和开发维护资料按用途分别保存。脚本是否需要保留取决于任务用途，不取决于由人还是助手编写。

| 目录 | 内容 | 保留方式 |
| --- | --- | --- |
| `src/`、`scripts/`、`dist/` | 框架源码、固定入口与构建产物 | 随程序更新 |
| `runtime/` | 正式运行组件、源码部署副本 | 保护当前程序和回滚入口 |
| `data/` | 配置、凭据、数据库、会话、附件及业务状态 | 持久备份，按业务规则维护 |
| `workspace/<任务名>/` | 助手任务脚本、输入、中间结果和成果 | 默认保留，支持继续任务 |
| `private/extensions/<标识>/` | 私人可复用插件源码、文档和素材 | 独立维护 |
| `private/maintenance/` | 开发维护脚本、验收报告、模拟记录、发布产物和迁移备份 | 明确归档和保留期限 |
| `.cache/` | 可重建的开发依赖和缓存 | 不使用时可按工具规则清理 |

建议的任务结构：

```text
workspace/乐谱转换/
  scripts/   # PDF 处理、曲目修正和键位转换代码
  input/     # 原始资料
  output/    # 最终成果
  tmp/       # 可重建中间文件
```

助手预设引导使用这个结构，不强制把已有任务重新组织，也不自动删除 `tmp/`。有实际跨任务复用价值的最小能力可注册为框架插件；具体任务代码继续留在工作区。工作区不是安全沙箱，也不扩大权限。详见 [扩展开发](EXTENDING.md)。

跨任务经验通过 `workspace/README.md` 索引、相关任务的 `SKILL.md`／README 和按需读取的 `references/` 分级组织。先核对现有脚本再开发，避免通读全部工作区；调用约定和服务故障记录见 [工作区经验](WORKSPACE_KNOWLEDGE.md)。

## 启动与更新

默认管理配置为 `data/admin/config.json`。本机受管安装使用 `data/live/framework-admin.json`、`services.json` 和 `service-health.json`。显式 `--config` 和 `QQ_BRIDGE_FRAMEWORK_CONFIG` 环境变量优先；启动不会自动搬迁目录。原有自定义配置可继续通过明确路径启动。

账号内部的 `runtime/` 子目录是账号数据的一部分，例如 `data/admin/runtime/`。更新事务保存在 `data/framework-updates/`，更新控制记录和进程锁也位于 `data/`。程序更新与目录整理分别处理。

发行清单禁止覆盖 `data/`、`workspace/`、`runtime/`、`private/` 和 `.cache/` 中的文件。完整包包含 README、公开文档、示例、SDK 源码和组件包；脚本与插件开发可直接查阅安装包内容。Docker 持久卷保存 data、workspace 和 private，详见 [Docker](DOCKER.md)。

## 已有安装的整理顺序

1. 列出服务入口、配置、数据库、正在执行的任务以及仍被引用的附件路径，记录当前部署和会话绑定；先备份。
2. 停止使用待迁目录的任务后，归档已结束的开发脚本和验证资料到 `private/maintenance/`。不按扩展名批量移动所有脚本，不把报告当缓存删除。
3. 任务工作目录迁到 `workspace/`，同步明确的调用方；已有历史引用不能确认全部更新时保留兼容入口。不要通过改写聊天历史解决路径变化。
4. 持久数据可在维护窗口迁往 `data/`，必须同步配置中的路径、插件引用和恢复记录，并验证规范路径及身份校验。不能确认兼容时保留原路径，升级本身不强制迁移数据。
5. 启动框架后核对聊天、助手、插件、会话绑定、附件读取和实际模型调用。失败时按迁移记录恢复；不重置会话或重放未知任务。

默认模拟记录写入 `private/maintenance/simulations/`，索引仍保存实际绝对路径。旧模拟目录包含来源归属和执行证据，保留其原路径或完成专门的索引迁移后再移动。维护命令处理已登记的新模拟目录，保护最近四轮，超过三十天且无引用的旧轮次才参与回收。发行产物写入 `private/maintenance/releases/v<版本>/`；远端历史 Release 保留。

DSH 原生桥接包的持久归档位于独立 `DSH_HOME/packages/qq-bridge-framework/`，操作记录位于 `DSH_HOME/storages/qbf-bridge-management/`，由 DSH 所属安装保留。框架维护回收旧快照前检查已配置 DSH profile 的依赖声明和实际链接，保护仍被旧安装引用的程序；读取无法核验时停止清理。新安装不链接框架快照。
