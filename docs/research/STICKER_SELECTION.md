# 表情选图参考与改进方向

调研日期：2026-11-02。目标是在保持自然使用频率和合理耗时的同时，提高实际选中图片的适合程度；不要求唯一标准答案，也不把大量弃选当作准确率提升。当前运行行为见 [表情机制](../STICKERS.md)，下列演进建议尚未全部实现。

## 直接相关的参考

| 参考 | 实际采用的方法 | 对本框架的启发 |
| --- | --- | --- |
| [EIGML：Emotion and Intention Guided Multi-Modal Learning](https://arxiv.org/html/2511.17587v1) | 联合建模情绪与意图，并融合语义、情绪和意图的匹配结果 | 相同动作或相同正负情绪都不足以说明表情合适；撒娇式不满、拒绝、讽刺与认真生气需要结合目的区分 |
| [Int-RA：Reply with Sticker](https://arxiv.org/abs/2403.05427) | 先表示对话中的表达意图，再建模语境与候选图片的跨模态关系；区分用图回复和给文字配图 | 查询应描述机器人这次想表达什么，而不只是重复对方消息里的动作或情绪 |
| [MaiBot 表情包文字选择器](https://github.com/TogawaSakiko-desuwa/Maibot_Emoji_Select_With_Text) | 默认词法召回，支持可选语义召回；将短名单、说话方、最近对话和情绪提示交给文本模型重排，允许无匹配 | 可以继续利用已有描述和标签，不必先引入新向量服务；向量和关键词负责召回，最终选择需要语境判断 |
| [MaiBot 内置发送实现](https://github.com/Mai-with-u/MaiBot/blob/main/src/maisaka/builtin_tool/send_emoji.py) | 将候选图片拼图交给视觉子代理选择 | 描述不足以分清表情、动作或图中文字时，可按需增加少量实际图片复核，不要求每次看全库 |

这些论文的训练模型和公开数据集结果不能直接作为当前商用模型、私人图库的准确率。参考插件的行为说明也不等于本机验收结果。本轮借鉴判断维度与处理流程，没有复制这些项目的代码。

## 当前实现与不足

当前先按动作、用途、情绪、文字与描述召回，保留角色、否定、不适用语境及近期重复约束；排名第一且唯一明确命中动作或用途的候选可以本地选取，其余可交给独立文本模型。已补充明确情绪冲突的基本排除，例如仍在生气时不选仅表达开心、害羞的摸头图。

这类排除只是基本约束。实际交流中的娇嗔、反讽、故意装凶、被安慰后缓和不能完全靠正负词表决定。本地动作命中也不能证明图片的语气、人物立场和本轮表达目的都合适。主聊天的一至三个检索词适合召回，复杂情绪还需要保留给最终判断的表达信息。

## 建议的选图流程

1. 保留近期有说话方区分的语境，并明确机器人本轮的表达目的、当前情绪和准备发送的文字。分开发言者的情绪与机器人要表达的情绪，不把整个群的情绪作为机器人的固定状态。
2. 用已有描述、用途、情绪和动作多路召回。短名单数量通过本机样本比较决定，不为关键词完全一致放弃语义上适合的图；图库较小时先复用本地索引。
3. 由文本模型综合比较表达目的、情绪与强度、动作、图中文字和会话语气。动作只是一项证据；没有明显冲突但不够确定时，允许选择较贴切的候选，不要求每项标签完全相同。
4. 对描述含糊、反讽或相似图难分的少数请求，考虑实际图片复核。GIF 复用现有真实时间抽样，不以静态首帧代表完整动画。词义检索与图片复核分别测量耗时，避免全部请求都增加视觉调用。
5. 返回一个真实候选或无匹配，保持同一次候选快照与资源核验。正常文字继续发送，不随机换图补发。

是否保留本地直接发送，需要结合误选率与延迟比较。候选少或动作唯一只是减少歧义的条件，不能替代情绪与表达目的的一致性判断；模型自报的把握程度也不能直接当作经过校准的概率。

## 评估方式

准备同动作不同情绪、同情绪不同目的的对照，例如生气时被摸头、开心时被摸头、明确和好后的摸头，以及认真拒绝和玩笑装凶。每个场景允许多张图被人工判为合适，不限定唯一答案。

同时统计实际选图适合率、明显情绪反向的次数、存在合适素材时的选中比例，以及延迟、超时和模型用量。使用相同图库、语境与渠道比较现行匹配和候选重排；小样本通过只证明这些场景，不据此声称总体准确率。
