# 工作台视觉更新 · 静态设计案

本稿依据 2026-11-06 当前控制台实现制作，用于讨论视觉方向。打开 [index.html](index.html) 即可预览；无需安装依赖或启动服务。此提案尚未应用到正式 WebUI。

## 为什么现有界面显得复古

问题主要来自多个视觉选择叠加，而不是页面模块的排列。

| 当前实现 | 对观感的影响 | 本稿调整 |
| --- | --- | --- |
| 正文 12px，辅助文字 11px，页面标题 18px | 字号普遍偏小，浏览时需要逐项辨认 | 常用正文 13px，辅助说明 12px，标题 22px；时间等紧凑元数据单独处理 |
| 常用按钮 24–27px，面板内边距 10px，区域间距 8px | 文字、控件和边框挤在一起，类似早期桌面管理工具 | 常用控件约 28–32px，卡片内边距 14–16px，区域间距 12–14px |
| 页面、侧栏、卡片、摘要条及标题栏都带蓝灰底色 | 大片相近色阶使内容层级不清晰 | 中性浅灰页面、白色内容面板，紫色集中用于选中与主要操作 |
| 多层边框、底色条、日志隔行条纹 | 装饰与内容争夺注意力，表格感过强 | 保留区域边界，移除摘要底色条和活动隔行底色，使用轻分隔线 |
| 活动区域整体采用等宽字体，字号与行高都很小 | 普通会话内容也呈现终端日志的感觉 | 正文采用无衬线字体，仅时间保留等宽数字，行高从约 20px 调整到 33px |
| 标题、正文、提示和按钮尺寸接近；禁用按钮仍有明显紫色底 | 扫视时难以判断重点与可执行动作 | 用字号、字重与间距拉开层级；禁用动作采用中性底色，主要可用操作使用实色 |

事实依据：`web/console.css`、`web/console.tsx`、`web/components/ui/button.tsx`、`web/components/ui/input.tsx`、`web/components/recent-activity.tsx` 和 `web/pages/overview.tsx`。本机浏览器检测到当前中文实际回退至 WenQuanYi Zen Hei；字体呈现取决于客户端系统，不能把本机结果等同于所有用户设备。

## 保留的布局和操作方式

- 侧栏宽度仍为 192px，导航名称和顺序保留。
- 顶部仍放侧栏切换、当前位置、搜索、页内目录、连接状态、主题和退出。
- 概览仍为三张状态卡，中段为最近活动／当前聊天，底部为需要关注。
- 桌面中段维持 1.45:1 左右分栏，长列表和配置保留区域内滚动。
- 方案、人设、续聊、回复、媒体、访问和维护的分组顺序，以及各自保存入口保留。
- 详情和设置继续通过现有窗口方式进入；此稿重点绘制概览及版本窗口，不代表其他页面已完成设计。

更清晰的字号和行距会使同一高度显示的活动条数减少，右侧低频配置仍需要滚动。这是本稿的密度取舍，后续可依据实际使用反馈微调。

## 版本位置

`v1.12.0` 位于左上角“配置工作台”站名正下方，与站名左对齐，作为可点击的弱强调入口。点击打开“框架版本与更新”窗口，保留主动检查更新和发行说明入口。顶部右侧腾出的空间留给已有工具。

窗口展示源码安装的当前版本状态；版本号与状态均为固定演示值。发行包与 Docker 的更新能力仍按现有安装方式判断，本稿不改变更新策略，也不假定所有安装都支持网页更新。

## 预览范围

支持浅色／深色切换、活动来源筛选、侧栏折叠、手机导航、版本窗口、Esc 关闭，以及字段修改后的可保存样式。其他按钮会提示静态预览；保存、刷新、检查更新均不调用后端。所有名称、聊天内容、数量与时间都是合成示例，不读取当前会话或配置。页面 CSP 禁止连接请求。

源文件优先使用系统中文无衬线字体；Linux 可使用已安装的文泉驿微米黑。审阅用单文件离线导出和截图保存在被忽略的 `runtime/design-visual-refresh/`，单文件内嵌仓库已有文泉驿微米黑的字形子集，以便离线审阅时保持一致；该导出包含字体许可。字体来源与许可见 [字体资源说明](../../../assets/fonts/README.md)。源设计文件没有增加正式 WebUI 的字体依赖。

本次仅验证设计预览的渲染、响应式布局和上述演示交互。没有变更框架接口、聊天逻辑、生产样式或部署版本。

浏览器核对结果：1440、1280、1024、768、390、360px 均无页面横向溢出；版本弹窗、静态检查结果、Esc 关闭、手机导航、来源筛选、编辑后按钮状态和主题切换通过。离线导出没有脚本异常或 HTTP(S) 请求。截图及详细结果保存在同一运行目录，仅含合成数据；用于诊断的原界面截图单独标记为 `current-private.png`，不作为设计案分发。
