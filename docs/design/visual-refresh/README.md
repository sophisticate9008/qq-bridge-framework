# 工作台质感更新 · 同尺寸静态设计案

打开 [index.html](index.html) 查看离线稿。底部“原有表面／质感方案”切换使用同一份 DOM 和内容，只切换表面样式；右上角可选择日间或夜间。版本入口位于左上角站名下方。

本轮按用户最新要求收回上一稿的字号、留白与控件放大。正式 WebUI 尚未修改。

## 本轮约束

- 正文 12px、辅助文字 11px、标题 18px；沿用当前字体栈，不导入、替换或嵌入字体，不改字重、字距和行距。
- 侧栏 192px、顶栏 40px、导航行 32px、常用按钮 24px、输入框 27px、卡片内边距 10px、区域间距 8px；日志保持 20px 行高和等宽字体。
- 保留三张状态卡、活动／当前聊天分栏、需要关注区，以及原有配置分组和独立保存入口。
- 版本入口放在站名下方，占用原品牌区内部空间，不抬高导航起点。

`preview.css` 是依据当前实现复刻的紧凑布局和基础外观；`surface.css` 单独存放本次提议的质感样式。后者只定义颜色、背景、边框颜色／圆角、阴影、透明度和背景模糊，没有字体、尺寸、间距或定位规则。静态复刻用于讨论观感，不代替正式 React 页面。

几何与字体依据：`web/console.css`、`web/console.tsx`、`web/components/ui/button.tsx`、`web/components/ui/input.tsx`、`web/components/recent-activity.tsx` 与 `web/pages/overview.tsx`。

## 质感调整

| 部位               | 当前视觉特征                 | 提议的表面处理                                               |
| ------------------ | ---------------------------- | ------------------------------------------------------------ |
| 页面与卡片         | 蓝灰底色及边框构成大部分层级 | 雾灰底面、近白卡片，极轻投影与内侧亮边区分前后层次           |
| 卡片标题与分组     | 大片同类着色条、连续实线     | 透明度更低的标题底色与分隔线，保留原有占位和分组             |
| 侧栏选中与功能图标 | 单层平涂紫色块               | 克制的紫色明暗过渡、细微边缘亮度，明确选中和可点击状态       |
| 输入框             | 同背景色加外框               | 浅凹槽底色与内阴影，区别于凸起按钮                           |
| 普通／主要按钮     | 扁平边框或单色填充           | 细边缘、轻高光和短投影；主要按钮保留紫色，禁用按钮采用中性色 |
| 活动行             | 明显交替色带                 | 降低条纹对比，仅在悬停时强调当前行；密度和字体不变           |
| 夜间               | 偏蓝紫的平面色块             | 炭灰底面、柔和顶缘亮度与低强度投影；输入区稍暗               |
| 版本弹窗           | 常规边框与遮罩               | 面板双层阴影、背景模糊和清晰聚焦描边                         |

这一轮把“现代感”的判断集中到材质层次、色彩纯净度和状态细节，不以减少同屏信息量换取观感。

## 预览边界

- 支持同尺寸表面对比、主题切换、活动来源筛选、侧栏折叠、手机导航、版本窗口和编辑后的按钮状态展示。
- 窗口展示源码安装；“主动检查更新”仅展示固定模拟结果，不调用 GitHub。其他业务按钮提示静态预览，不保存配置或操作服务。
- 所有聊天内容、名称、数量和时间均为合成示例；CSP 禁止连接请求。
- 底部比较开关属于审稿工具，不会加入正式产品。
- 截图、单文件离线导出与核对结果位于忽略目录 `private/maintenance/design-surface-refresh/`。字体完全使用当前系统和正式页面相同的字体栈，导出没有字体文件。

已在 1440、1280、1024、768、390、360px 的浅色／深色共 12 组场景逐元素比较：467 个工作台元素的矩形坐标、尺寸、字体、字号、字重、行高与字距在两种表面间完全一致，页面均无横向溢出。浏览器解析后的质感规则只有颜色和绘制相关属性；版本窗口、来源筛选、手机导航与 Esc 关闭通过，无脚本异常和 HTTP(S) 请求。

正式实现仍需在实际 React 组件上核对各页面状态。本轮不变更生产样式、接口、聊天逻辑或部署版本。
