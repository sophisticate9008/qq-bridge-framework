# 验证范围

框架将源码检查、协议集成、浏览器操作、真实期限、发行安装与模型行为分别验证。模拟协议的发送回执只表示本地捕获；接口可连接不证明模型生成、工具执行或 QQ 送达。

## 持续集成

日常“框架验证”运行 Git 凭据扫描、严格类型检查与快速测试。手动“完整验证”补充源码规则、架构边界、集成、真实期限、构建产物、SDK、浏览器与桥接插件检查。命令与分组见 [运行手册](OPERATIONS.md#开发检查与测试)。

SDK 验证在独立项目安装组件包、严格编译并运行；DSH 桥接插件的测试使用实际 SDK 与隔离服务，不连接使用者的生产账号。浏览器场景使用隔离配置，不能据此宣称真实模型质量已经通过。

## 发行包验证记录

已核对的 v1.9.0 对应提交 `ea597f27de3f6ef526b99c673af780e70eb1c31a`。该提交的[框架验证](https://github.com/sophisticate9008/qq-bridge-framework/actions/runs/41436815231)与[发行包安装验收](https://github.com/sophisticate9008/qq-bridge-framework/actions/runs/41436815350)均成功。

框架 TAR 与 Windows ZIP、SDK 和 DSH 桥接插件包由同一候选源码构建，附件使用 `SHA256SUMS` 校验。平台验收分别使用真实 Windows x64、Linux x64 与 Linux ARM64 runner，覆盖依赖安装、初始化、中文原生排版、网页资源、令牌保留及重启。发行包保留源码，但运行入口使用预编译后端；安装验收不要求开发机环境。

## v1.11 真实模型模拟

本轮使用当前配置的真实模型渠道和独立 DSH，模拟 QQ 入站并在本地捕获回复。隔离会话加入不进入模型正文的合成历史记录，旧式开场实测 `2,464,805` 字节，超过原 `1 MiB` 帧上限；新事件接口完成群聊、重启后的接话和私聊能力查询共三轮，捕获三条回复。重启前后 sessionId 保持一致，持久游标恢复并继续前进，第二轮正确回答第一轮约定的暗号。持久工具记录确认实际调用 `qbf_capability_catalog` 与 `qbf_reply`，宿主未报告监听故障。

原故障会话另外通过只读新接口建立监听，生产会话、历史和配置均保留。真实模型模拟验证了本轮场景，回复只送本地捕获端；实际 QQ 送达与持续长时间运行仍分别观察。原始配置、对话、日志及合成历史保存在私有维护目录，不进入公开包。

## 诊断与恢复边界

助手失败通知维护（未发版）：失败事实通过原父会话模型按当前人设转述，群聊附实际主人 mention，发送使用真实回执；不直接发送固定模板。隔离模拟完成真实 QQ 入站、聊天模型委派、真实 GPT 请求与工具调用，再注入 `Upstream HTTP/2 stream failed`，DSH 原记录确认 `PI_AI_ERROR`；原聊天模型实际生成自然语言失败说明，捕获端确认送达，重启后原会话、unknown 工作与去重记录保持，没有重提任务或重复通知。该轮工具调用参数被 SDK 拒绝，未声称文件操作成功。模拟消息只发本地捕获端，不修改 DSH 程序。群／私聊的正常转述、模型失败、投递未知、过期回复、主人变更及禁止再次委派均有协议集成验证。定向覆盖 133 项，首次混合并行回归的两项既有短期限恢复测试未达到初始状态，单独复测通过；严格检查及本机构建通过。

2026-11-05 助手部署维护（未发版）：166 项定向回归通过，覆盖依赖路径变化、未知部署不重试、校验期间文件变化、任务受理前的准确拒绝、只读健康检查及原有聊天／工作恢复；严格类型、源码规则与本机部署构建通过。真实模型模拟先完成一次聊天委派与助手命令／文件操作，再在隔离目录注入旧路径对应的部署版本，重启后核对原聊天会话及助手预设保留、部署版本同步、历史工作没有重跑，并完成第二次真实委派。两份结果文件内容及本地捕获附件字节均通过核对。此验证使用真实聊天和助手模型，QQ 输入与回传仍为本地模拟，不代表生产 QQ 端已实测。

QQ 消息接收、HTTP 发送、DSH 鉴权接口、会话回复监听、工具通道与框架宿主分别检查。状态读取不发送模型请求，也不重启服务。外部服务恢复后需要核对框架的实际连接与聊天状态；结果未知的旧请求不会自动重发。

故障恢复验证应保留各环节中断时的状态、诊断、恢复操作和恢复后的证据，区分自动重连、明确重启框架与外部服务维护。具体使用见 [恢复手册](RECOVERY.md)；当前源码的针对性回归位于 `test/`，实际环境中的原始记录由运行者私有保存。
