# 内置 Markdown 图片排版

框架把 Markdown 排版为 PNG，通过普通图片消息发送。无需安装浏览器，也无需在协议端开启特殊 Markdown 消息支持。普通闲聊保持文字；纯文本长文仍按“长文合并转发”设置处理。

## 使用

在 QQ 中直接提出“把这段内容排版成图片”“把表格和公式渲染成图”。模型可以明确选择图片排版；回复中的明显 Markdown 文档结构也可由输出层识别。图片由框架实际生成并登记到当前会话，再交给现有发送链路。渲染完成与 QQ 确认送达分别记录。

渲染能力属于框架内置输出服务，协议适配器只负责发送生成的图片。NapCat 与 SnowLuma 使用相同的图片内容，不各自实现一套排版。扩展可以复用 `MarkdownRenderer` 接口；本机文件读取和助手执行权限不由排版功能授予。

模型输出协议可以明确选择图片格式，不能同时混入 `content` 或普通回复正文：

```json
{"schema":"qbf.output/1","format":"markdown-image","body":"# 使用说明\n\n这里是正文。","title":"可选标题"}
```

`body` 最多 32000 个 UTF-16 码元且不超过 64 KiB；标题最多 120 个码元。默认页宽 1080 像素、页高上限 1800 像素，最多六页；单次渲染最长 12 秒，同一渲染服务最多同时处理两份文档。生成的图片仅在原账号、会话及其当前绑定版本内使用，有效期 24 小时。

公式不另设数量、单条源码长度、总源码长度或独立公式行数配额，沿用整份文档的输入边界。重复的同模式公式复用本轮排版结果。渲染按实际耗时、工作线程 JavaScript 堆预算、图形尺寸与字节、文档页数和最终 PNG 字节限制执行；默认线程老生代 128 MiB、新生代 32 MiB，整份及分页 PNG 总字节分别不超过 16 MiB。超时、线程内存不足、页面过大和输出过大分别报告对应原因。公式语法须有效，动态加载、外部资源及任意 HTML 命令继续禁用。

## 排版范围

- 中文与英文、标题、段落、粗体、斜体、删除线、行内代码。
- 有序与无序列表、任务列表、引用、分隔线和表格。
- 围栏代码块与常用语言高亮；未知语言按原文显示。
- 行内与独立公式，使用本地数学排版组件生成图形。
- 正文、表格和代码中的常用 Unicode 数学字形，包括导数撇号、上标括号、数学斜体字母、数集、积分、集合关系及箭头。
- 长内容按版面分页，限制输入、页数、像素和输出字节；超出边界明确报告，避免静默截掉后文。

Markdown 中的链接显示为文字，不访问目标网页。图片引用显示说明占位，不自动下载外部 URL 或读取本机路径。原始 HTML、脚本和任意页面 CSS 不执行。Mermaid 等图表语言不属于当前内置绘图范围，按代码展示，后续可通过扩展接入。

正文中的 `f‴(x)`、`f⁽ⁿ⁾(x)`、`𝑓(𝑥)`、`ℝ`、`∭` 与 `⟹` 通过本地字体回退显示。分式、极限和复杂上下标使用公式语法：行内 `$...$` 或 `\(...\)`，独立公式 `$$...$$` 或 `\[...\]`。例如 `$f'(x)=\lim_{h\to0}\frac{f(x+h)-f(x)}{h}$`。

## 实现与部署

解析沿用 `markdown-it`，排版与 PNG 输出使用 Takumi 的本机组件，代码高亮和数学公式组件在渲染侧加载。中文主体字体与数学、符号及扩展文字字体随框架分发，按固定顺序回退；运行时直接读取随附文件，无需系统字体或网络字体下载。构建和完整安装包同时包含这些字体。

依赖版本固定在项目锁文件中。重新部署时同时包含渲染源文件、安装后的依赖与字体资源。第三方项目与字体许可见 [NOTICE.md](../NOTICE.md) 和字体目录中的许可文件。
