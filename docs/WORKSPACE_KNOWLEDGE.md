# 工作区经验与服务排查

助手通过文件读取工具按需查阅经验，复用已核验的脚本和调用方法。经验文档不会自动注册工具、安装依赖或增加权限，也不要求每项任务创建插件。

## 分级读取

1. `workspace/README.md` 是简短能力索引，只保存能力、适用条件和入口链接，不放长日志或脚本正文。
2. `workspace/<任务名>/SKILL.md` 保存相关能力的使用说明；已有清楚的 README 可以作为入口，避免重复维护。
3. `references/` 保存需要时才读的参数说明、排错和复现记录，`scripts/` 保存实际执行程序。原始输入与成果继续放在 `input/`、`output/`。

开始任务先读索引，再选择相关入口，最后按需读取具体参考资料。索引不存在时，按任务关键词搜索目录和文件名；不要递归读取全部任务、依赖、历史会话或资料。助手预设只提供这一查阅约定，不把工作区全文注入模型，也不自动扫描执行其中的文件。

可复用说明至少包含：

- 能力用途与适用条件，以及不适用的输入。
- 脚本入口、参数、工作目录、依赖与调用示例。
- 输出位置、权限、网络与写入副作用；复用时将新成果写入当前任务，保留旧成果。
- 实际验证的环境与范围、已知限制、最后验证日期。
- 必要的详细参考链接；已有服务故障单独保留状态与证据。

先核对已有实现再决定复用、修正或新写。任务完成后只沉淀已核验的跨任务经验，索引保持简短。私人经验留在忽略的工作区；不复制凭据、私人输入、完整会话或不必要的账号信息。经验内容仅供参考，执行继续服从当前用户要求和宿主权限，不能把旧说明当成操作授权。

## 服务接入失败

先确认失败的是框架服务、模型工具、DSH 插件还是 MCP 服务。框架服务由包发布并由声明依赖的消费者取得；模型工具需要实际注册，并在对应会话范围可见且有执行权限。发布服务不会自动产生模型工具。助手是独立 DSH 会话，聊天会话中的工具可见性不能代替助手会话的实际验证。

按以下顺序收集证据：

1. 核对实际安装版本与当前版本文档、SDK 导出，确定预期接入点。
2. 核对可信 bootstrap 登记、包依赖和服务 `provides`／`requires`，或 DSH/MCP 所属配置与实际加载范围。只存在源码不算已登记。
3. 核对提供方运行状态、实际工具名称、目标会话可见性及当前权限，不根据名称或目录猜测已就绪。
4. 做无破坏性的最小调用，记录失败阶段、标准错误码和脱敏证据。没有原始错误时保留“原因未确认”，不推断接口不支持。

模型使用 `qbf_capability_catalog` 按需发现扩展工具：无参数先看分类，`category: "extensions"` 查扩展摘要，`id` 查完整参数。`query` 将空格分隔的多个关键词同时匹配工具名称、说明与分类名称，例如 `PDF 扩展`；目录只返回当前可发现的工具，不执行处理。搜索无结果时再检查实际分类和登记状态，不能单凭一次查询为空断言服务挂载失败。

遇到 SDK 导入的 `ERR_MODULE_NOT_FOUND` 时，从扩展自身目录检查包解析。发行包中的 SDK 归档和框架进程可运行，并不表示扩展目录已经安装了 `@qq-bridge-framework/sdk`。按 [SDK 安装说明](../packages/framework-sdk/README.md) 在扩展自身的包中使用已校验的对应 SDK 归档，保留其依赖与锁文件；不要改为导入内部源码或给 DSH 全局安装框架 SDK。SDK 导入成功后仍需完成包登记、加载与实际调用验证。该错误只在取得实际导入失败证据时采用，不能作为所有挂载失败的默认解释。

交付分别报告任务成果、服务接入状态和待处理问题。使用脚本完成任务只证明脚本可用，不能把未接入服务标为已修复；用户明确要求插件时仍需交付插件。已有加载记录可能不足以还原历史原因，应准确说明证据范围。

保留现有 bootstrap、权限及其他服务。已登记的兼容实现更新使用既有热重载入口；新增工具、schema、依赖或固定入口变化通过完整应用流程处理。不要为尝试挂载擅自重启外部 DSH 或协议端，结果未知时先查询原操作。接入细节见 [扩展开发](EXTENDING.md)、[服务规范](SERVICE_CONVENTIONS.md) 与 [DSH 接入](DSH.md)。
