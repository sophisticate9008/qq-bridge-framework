# 助手结果附件

助手调用 `qbf_work_attach({path, filename?})` 申报本次工作的现有文件。旧的 `kind: 'image' | 'file'` 参数继续接受，省略时由宿主读取文件头识别；模型可见schema仅声明必需path，开放参数对象在执行入口继续验证可选filename与旧kind；工具不要求模型填写账号、work、session 或 generation。可信宿主从当前被准入的助手调用上下文补齐身份并签发 opaque 资源编号。返回 `registered: true, sent: false` 只表示登记，最终以原 QQ 会话 outbox 的实际回执为准。每次工作最多三个不同附件。可选filename/kind的空串或null按未提供处理，兼容模型工具包装器的默认值。

## 签发与归属

文件系统宿主由配套 DSH 桥接插件提供。它在 `storages/qbf-work-paths/` 保存编号、文件描述及工作作用域；账号标识由框架随可信工作请求传入，parent session、child、work 和 generation 从当前助手租约取得。模型只能申报候选路径，不能指定白名单、修改作用域或签发编号。受信桥接是宿主的文件系统访问适配器，并非模型侧附件存储。

白名单根目录由部署装配提供：部署工作目录下的 `workspace/`（部署目录本身名为 `workspace` 时使用该目录），以及当前 DSH home 的 `sessions/`。cwd 变化不扩大白名单；不开放 `/`、`/root`、项目根目录或任意模型提供的根目录。相对路径按实际助手 cwd 解析。请把产物放在 `workspace/<任务>/`。

签发与发送解析使用同一验证器：realpath、普通文件、单硬链接、父目录身份、存在性、大小、mtime/ctime、dev/inode，以及全量流式 SHA256。256 KiB 缓冲顺序读取全部文件，不采样，不把文件整体读入内存；普通文件和图片均不复制进附件库。工具识别图片只额外读取文件头，协议端仍负责实际媒体接纳。

框架接收编号后保存账号、QQ 会话、parent session、工作及 generation 的聊天映射；不重新签发文件描述或重复实现路径验证。聊天通过已注册的 `qbf_work_resolve({resourceId})` 取得实际读取方式；真实工具scope补齐账号、会话与代次，不接受模型提供工作身份。它可解析该会话已登记的原始编号或聊天映射编号，返回共享路径或一次性HTTP流通道。聊天和 outbox 只使用资源编号。发送前框架重新检查当前账号、白名单与会话代次，再向文件系统宿主解析原编号；宿主核对工作归属并全量复验文件。

## 本机路径与远程流

`verifyWork.pathAttachmentsSupported` 和 `startWork.attachmentTransport: 'path-v1'` 表示编号登记能力。框架与桥接插件需要配套升级；新宿主在verify/start阶段要求该能力；缺失即明确拒绝新工作，不启动旧字节工具。既有历史仍可读，不选用字节回退。回环部署默认共享文件系统；端口转发、容器挂载隔离或跨机部署应在可信适配器装配中设置 `sharedWorkFilesystem: false`。

共享文件系统返回经复验的绝对路径。远程解析通过已鉴权的 `readWorkPath` RPC 申请一次性 HTTP 通道，由 DSH `webServer` 提供 `/qbf-work-stream/<随机能力令牌>`。通道按背压直接从原文件描述符流向读取方，逐段计算完整 SHA256，并在最后一段完成前检查完整性；不使用 Base64 分页，不生成中间附件文件或全量副本。每个资源最多保留一个未消费通道，重新解析替换旧通道；通道随一次HTTP请求结束、显式撤销或桥接卸载撤销。聊天工具取得的未消费通道在当前聊天执行释放时按精确token关闭，未知读取不自动重试；失败需显式重新解析原编号。地址含读取能力，不应记录到公共日志。

框架将专用流 URL 交给既有 OneBot URL 文件读取能力。跨机时协议端必须能够直接访问 DSH 的该地址；反向代理需保留原路由并允许流式响应，公开网络应使用 HTTPS。通道采用单次GET，不提供HEAD预探测、Range或断点续传。DSH 没有 `webServer`、协议端不支持 URL 读取或网络不可达时明确失败。远程验证覆盖官方 SDK 的真实 HTTP RPC、流路由和 100 MiB 全量读取；不将这一结果表述为所有远程 QQ 部署均已验证。共享路径同样要求协议端能访问该路径。此版本不扩展协议端发送实现。

## 生命周期、错误与迁移

新资源不设固定小时 TTL、总字节配额或登记项数阈值。有效性依赖原工作归属、文件完整性和送达状态；确认该附件送达后撤销DSH登记与全部未消费通道，并删除框架短时映射；保留原outbox/投递证据和原文件。未知或拒绝投递撤销未消费通道，保留原编号、完整性描述与失败记录，供人工核对，不自动重放。未核清工作可能长期保留少量元数据，这是保护未知证据的保留策略；它不保留任何文件副本，也不会因重复解析累积内存ticket。确认后的清理失败记录诊断并保留禁止重发标记，不会把已确认回执降为unknown。重启恢复持久描述及工作绑定，不重新执行助手；旧描述原有 TTL 仍按原记录处理，失效后不复活。

删除、篡改、路径逃逸、父目录交换、跨会话借用及代次变化均明确拒绝；文件失效返回“文件已失效”。不会返回空附件、以文字替代附件或静默转字节。登记后到确认送达前，请保持原文件不变。

1.13.4 按维护者明确约定作为补丁交付这次附件迁移。助手→聊天的 SDK 字节保存、聚合读取、Base64 回传及其 8 MiB 阈值已经废弃。`readWorkAsset` 和适配器 `readAsset` 仅保留明确报错的废弃入口，不能继续发送旧字节资源；旧工作、outbox 与失败记录仍可读取，需在原工作中明确重新登记现有路径，未知投递不得换键重放。旧调用 `qbf_work_attach({path,kind?})` 无需补上下文；自定义字节附件生产者需迁移到路径登记。框架、SDK 与桥接插件配套升级，不承诺旧字节接口行为兼容。其余公开配置、会话及 SDK 能力保持原兼容范围。

剩余图片入模、表情、排版、模拟入站素材等 8 MiB 限制属于独立资源或协议领域，不参与助手结果文件传输。协议端自身的文件大小、格式、网络与上传超时限制仍由实际回执决定。

TOCTOU 边界：共享路径复验后，协议端会独立打开文件；框架无法阻止同 UID 进程随后修改该路径。远程通道固定已打开的文件描述符并核对完整流，但不能撤回读取方已经收到的前缀。可信本机扩展和有全本机权限的助手不是恶意代码沙箱。本版通过明确失败与真实回执呈现边界，不创建大文件快照。回滚需同时还原宿主与桥接插件；新编号不应交给旧字节实现重放。

文件系统宿主在Linux使用原POSIX所有者与0700/0600权限检查，在Windows使用与框架相同的owner/SYSTEM/Administrators SID私有ACL策略，拒绝额外允许ACE及重解析点。新建私有目录和登记文件设置对应ACL；已有不安全存储明确拒绝，不静默跳过。Windows不支持目录fd fsync，journal保留文件fsync与原子rename；实际附件、重启与ACL验证由真实Windows runner执行同批组件包。

发送前普通文件解析拒绝以可选errorCode持久到outbox和工作deliveryError；WORK_PATH_INVALIDATED在工作界面及状态工具解释为“文件已失效，附件尚未上传”。诊断只保存白名单错误码，不含私有路径或异常正文；已进入协议端的未知发送语义保持不变。
